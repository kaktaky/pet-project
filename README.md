# Дневник питания

Личное приложение на FastAPI и SQLite: дневник калорий и БЖУ, вода,
план питания, история веса и статистика. Интерфейс рассчитан на телефон,
поддерживает светлую и тёмную темы системы.

## Запуск

Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

Открой http://127.0.0.1:8000. Для разработки:

```bash
uvicorn main:app --reload
```

Переменные окружения: `CALORIES_DB` — путь к базе (по умолчанию
`calories.db`), `HOST` — адрес (`127.0.0.1`), `PORT` — порт (`8000`).
Даты дневника используют часовой пояс компьютера, на котором запущен сервер.
Для доступа с телефона в домашней сети можно явно задать `HOST=0.0.0.0`.
Это приложение для одного пользователя, без разделения аккаунтов.
Оформление и графики загружаются с CDN и требуют интернета.

## Что бы съесть?

На главной нажми **«Подобрать еду»**. Приложение предложит блюдо или
сочетание двух продуктов из избранного, учитывая оставшиеся калории.
Для одного приёма подбирается до 600 ккал; при меньшем остатке варианты
укладываются в него. Калории и БЖУ берутся из твоих записей.

Ползунки меняют порции от ¼ до 3 с шагом ¼. Числа пересчитываются сразу;
при превышении цели появляется подсказка. **«Другой вариант»** переключает
предложения, **«Я это съел»** добавляет выбранные продукты в дневник.
Повтор одного запроса не создаёт дубликаты.

Укажи значения **на одну привычную порцию**, добавляя продукт через подбор
или профиль. Блюда с нулевой калорийностью остаются в избранном, но не
участвуют в автоматическом подборе. Пустое избранное больше не заполняется
стартовыми блюдами при перезапуске.

## Остальные изменения

- Кнопка ✎ в дневнике редактирует название, калории и БЖУ без начисления опыта.
- В плане можно скопировать меню на другой день. Оно добавляется к уже
  запланированным блюдам; копирование в тот же день запрещено.
- При первом обращении в новый день вчерашний дневник и вода автоматически
  архивируются. При ручном закрытии дневные итоги учитывают уже сохранённое.
- Нулевые калории не приводят к потере записей с БЖУ при архивации.
- Одинаковый вес можно фиксировать в разные дни; повторный замер за сегодня
  обновляет сегодняшнюю точку.

Схема SQLite обновляется автоматически при запуске. У старых записей
дневника нет даты, поэтому при первой миграции они относятся к дню запуска.
Перед обновлением сохранена локальная копия исходной базы:
`backups/calories-before-improvements.db`. Резервные копии исключены из Git.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
node --check static/suggestions.js
node tests/test_suggestions.js
```

Проверки используют временные базы и не изменяют `calories.db`.
